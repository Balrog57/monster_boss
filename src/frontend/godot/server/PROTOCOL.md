# Protocole multijoueur Boss Monster (serveur Godot headless)

Lancement : `godot --headless --path src/frontend res://godot/server/Server.tscn -- --port=8091`
Options : `--turn-timeout=70` (s, 0 = sans minuteur) `--adventure-timeout=10` `--bot-delay=350` (ms entre deux coups d'IA)
`--ttl=3600` (s, salle sans humain connecte) `--max-rooms=200` `--seat-grace=30` (s, voir Nettoyage) `--away-grace=10` (s, voir `away`) `--abandon-grace=120` (s, voir Nettoyage) `--public-idle=120` (s, voir Nettoyage).

Transport : WebSocket, **trames texte JSON**, un objet par trame avec un champ `t` (type). Une connexion = une salle = un siege.
Derriere nginx : proxifier `/ws` vers `localhost:8091` (Upgrade/Connection) ; le client web derive `ws(s)://<hote-de-la-page>/ws`.
Les cles entieres des dictionnaires (`players`, `stackPassed`...) voyagent en texte ; `NetCodec.decode` les restaure.
**Version** : `create`, `join`, `resume` et `listRooms` portent `v` = `NetCodec.PROTOCOL_VERSION` (entier, 1 aujourd'hui ; equivalent de l'`AppVersion` Photon). Tout autre `v`, ou son absence (onglet reste ouvert sur un ancien client), est refuse : `error` `version`, rien n'est cree, rejoint ni liste. A incrementer a chaque changement incompatible de message. `ping`, `move`, `sync`, `start`, `leave`, `away`, `setTitle` n'en ont pas besoin (ils ne s'adressent qu'a une session deja ouverte).

## Client -> serveur

| t | champs | effet |
|---|---|---|
| `create` | `v`, `name`, `public` (booleen JSON, defaut `false`), `title`, `players` (2-4 ; 5-6 exigent `crash-landing` dans `sets` et refusent `players-choice` et `players-choice-wiki` (seuls paquets sans regle de taille de paquet de heros ; `next-level`, `minibosses`, `tools-wiki`, `iod` sont admis) ; sinon `error` `bad_setup`), `sets` (ids de paquets, base toujours present ; les variantes de jeu du livret TNL (`Variants.gd`, cochees seulement avec la case wiki) y voyagent comme jetons `classic-wiki`, `hard-wiki`, `choose-wiki`, `machinations-wiki`, `unlimited-wiki` : le serveur les garde dans `sets` (donc dans `lobby.sets` / `rooms.sets`), `Match.new_match` les range dans `G.variants` (ids sans suffixe, cle publique de la vue) ; ils ne comptent pas comme des paquets pour la regle 5-6 joueurs), `bots` (0..players-1 : sieges IA prerempli), `turnTimeout` (s, defaut serveur), `avatar`, `wins`, `defeats` (profil affiche en salle d'attente, optionnels) | cree la salle (code de 4 lettres majuscules sans I ni O, comme l'APK ; collision => nouveau tirage), l'hote prend le siege 0. `public: true` (seul le booleen JSON compte, pas le texte `"true"`) la rend visible dans `listRooms` ; sinon elle est privee et jamais listee (le code est son seul secret). `title` : nom affiche dans la liste (nettoye comme `name`, meme filtre pour le nom de tout joueur : espaces rognes, 25 caracteres au plus ; defaut `<nom de l'hote>'s game`). Le setup est valide de la meme facon pour une salle publique (`bad_setup`). |
| `join` | `v`, `code`, `name`, `avatar`, `wins`, `defeats` (optionnels, comme `create`) | prend le premier siege humain libre ; le code est sensible a la casse (4 caracteres a-z 1-9) ; salle pleine => l'hote lance avec `start` |
| `resume` | `v`, `code`, `seat`, `token` | reprend un siege (reconnexion, rechargement de page) ; rend le siege a l'humain si l'IA l'avait pris |
| `start` | - | hote seulement : lance la partie, les sieges vides deviennent des IA |
| `move` | `move: {type, args}` | doit etre exactement un coup de `Match.legal_moves(seat)` (vocabulaire de Match.gd) |
| `sync` | - | renvoie lobby / etat courant |
| `leave` | - | salle d'attente : libere le siege ; si c'est l'hote, le role passe au premier autre humain connecte (APK : Photon designe un nouveau maitre ; `lobby.host` change, la salle reste ouverte), et s'il n'y en a aucun la salle se ferme (les autres recoivent `closed`, pas celui qui part) ; en partie : l'IA garde le siege definitivement et le siege est marque `left` |
| `setTitle` | `title` | hote seulement, salle d'attente (`status == "open"`) : renomme la salle. Le titre est nettoye cote serveur (frontiere de confiance) : doit etre une chaine ; caracteres de controle (< 32, 127-159), formats invisibles et surcharges bidi (U+00AD, 061C, 200B-200F, 2028-202E, 2060-206F, FEFF) retires, espaces rognes, 25 caracteres au plus. Vide apres nettoyage ou pas une chaine => `error` `bad_message` ; pas l'hote (ou hors salle) => `forbidden` ; partie lancee => `bad_state` ; le titre reste inchange. Sinon `titled` a l'emetteur, `lobby` (avec le nouveau titre) a toute la salle, et la liste publique repousse la ligne. Le meme nettoyage s'applique au `title` de `create`. |
| `listRooms` | `v` | repond `rooms` (liste des salles publiques, voir plus bas) et inscrit la connexion aux pushes `rooms` tant qu'elle n'est dans aucune salle |
| `away` | - | salle d'attente seulement (`status == "open"`) : l'onglet annonce sa fermeture (evenement navigateur `pagehide`, envoye par `OnlineClient._on_pagehide`). Le siege est marque `away` ; si la liaison tombe, il est libere apres `--away-grace` (10 s) au lieu de `--seat-grace` (30 s), `resume` avant ce delai le garde. Il n'y a pas de reprise automatique au demarrage du jeu : apres un rechargement de page, le siege n'est garde que si le joueur appuie sur RESUME (menu WITH FRIENDS) dans ces 10 s ; sinon un invite rejoint avec le code, et l'hote d'une salle privee n'est jamais libere. C'est le compromis avec un `leave`, qui ne laisserait aucune reprise. N'est pas un `leave` : l'hote d'une salle privee n'est jamais libere, et en partie le client n'envoie rien (la liaison coupee suit le chemin habituel, voir Nettoyage). Un `ping` ulterieur (page restauree du cache) retire la marque. Sans reponse. |
| `ping` | - | `pong` (le client en envoie un toutes les 20 s ; 120 s de silence = deconnexion ; un onglet endormi qui se reveille reping aussitot, rouvre la liaison avec `resume` si elle est morte) |

## Serveur -> client

- `joined` : `code`, `seat`, `token` (secret du siege, a garder), `host` (bool).
- `titled` : `title` (titre nettoye) ; reponse a `setTitle`, a l'emetteur seulement.
- `lobby` (avant la partie, a chaque changement) : `code`, `public` (booleen : salle visible dans la liste ; le client le relit apres une reprise, OnlineRoomInfo.IsPublic), `status` (`open|running|finished`), `numPlayers`, `seats: [{name|null, bot, connected, left, avatar, wins, defeats}]` (`left` = le joueur a quitte la partie en cours (`leave`), pas une simple coupure : le client en tire « X has left the game. » ; `avatar` = nom de fichier d'avatar sans extension, "" si inconnu ; `name` borne a 25 caracteres ; `wins` / `defeats` = compteurs locaux du joueur, cosmetiques), `sets`, `host`, `title` (titre de la salle, tel que la liste publique l'affiche).
- `state` (en partie, apres chaque coup ; contient aussi les champs de `lobby`) : `seat`, `view` (G filtre pour CE siege, format de `Match.G`),
  `moves` (coups legaux de ce siege), `deadline` (ms unix de fin du delai en cours, 0 = aucun), `awaited` (sieges humains dont une decision bloque la partie : le client affiche le compte a rebours quand son siege y figure), `serverTime` (le client en deduit le decalage d'horloge), `plays` (les 8 derniers sorts / capacites joues, tous sieges : `[{n, seat, move: {type, args}, card}]` ; `n` croit sans fin, `card` = la carte jouee en clair puisque la main de l'auteur est cachee ; le client emet la bulle « HAS PLAYED A SPELL / ROOM ABILITY » une seule fois par `n` pour les sieges autres que le sien, le premier etat recu ne fait que poser le repere).
- `error` : `message`, `code` (`bad_message|bad_setup|bad_move|busy|full|not_found|bad_token|forbidden|bad_state|no_seat|illegal|version`). `version` : voir Version ci-dessus (ne compte pas dans l'anti-force-brute). `bad_move` : le champ `move` de `move` n'est pas un objet. Un coup illegal (`illegal`) est suivi d'un `state` de resynchronisation. Anti-force-brute : 5 echecs `join`/`resume` (`not_found`/`bad_token`) sur UNE connexion la coupent (1008) ; les messages suivants de la meme rafale ne sont pas traites. Un joueur n'est donc plus bloque par les essais d'un autre (avant le lot 3.1, un compteur global de 5 echecs/s faisait repondre `busy` a tout le monde). Il reste une soupape globale (100 echecs `join`/`resume` par seconde sur tout le serveur : au-dela, `busy` sans consulter les salles), inatteignable par une seule IP derriere nginx. Le nombre de connexions neuves par IP est borne par nginx (`limit_req`, voir plus bas).
- `closed` : la salle n'existe plus (dernier humain parti, TTL, salle publique abandonnee). `pong`.
- `rooms` : `rooms: [{code, title, host, numPlayers, free, sets, status}]` ; reponse a `listRooms`, et PUSH envoye aux connexions qui ont demande la liste et ne sont dans aucune salle (la demande est oubliee des qu'elles entrent dans une salle : redemander apres un `leave`). Le push part des que la liste change (creation, jonction, depart, demarrage, fermeture, siege fantome libere), regroupe : au plus un controle par 250 ms. Le filtre de la liste (texte sur le titre / l'hote, ou nombre de places) est fait par le CLIENT (`OnlineMenus.filter_rooms`) : le serveur renvoie toujours la liste complete. Contenu : salles `public` ET `status == "open"` ET `free > 0` uniquement (une salle pleine, en cours ou terminee n'est jamais listee), 50 entrees au plus dans l'ordre de creation ; `host` = nom de l'hote, `title` = titre nettoye, `free` / `numPlayers` = sieges libres / total, `sets` = paquets actifs, `status` = `open`. Jamais de jeton, d'identifiant de connexion ni de detail de siege ; un salon prive n'apparait jamais.

## Regles serveur

- Autorite : seul Match.gd (serveur) applique les coups ; le client n'envoie que des coups proposes dans `moves`.
- Minuteur : une decision attendue d'un humain (choix en attente, choix de boss, pose initiale, fenetre de sorts, pause d'aventure, tour de construction)
  a `turnTimeout` secondes (10 s pour une pause d'aventure). A l'echeance l'IA (AI.gd) ne joue QUE la decision expiree (DONE automatique pour le tour de construction, comme l'APK, `GamePlayBaseScene.cs:272,1030-1042`),
  puis l'humain reprend la main avec un nouveau delai. Seul un siege sans liaison a l'echeance (ou ayant fait `leave`) reste a l'IA, jusqu'a son `resume` pour le premier.
  Le delai appartient a la fenetre de decision : en construction, `buildRoom` / `undoBuild` ne le repoussent pas, et un `resume` ne le relance pas.
  `--turn-timeout` vaut 70 s par defaut (la barre du bouton DONE de l'APK). Aucun etat n'est persiste : salle supprimee `ttl` s apres le dernier humain, 10 min apres la fin de partie.
- Capacite de salle (`activateRoom`, hors All-Seeing Eye) : comme un sort, c'est une transaction de la pile (`view.stack`, entree `type: "ability"`, `roomUid`, `card` = la salle). Les autres sieges recoivent leur fenetre de reponse (`pass` ou sort), elle se resout au dernier `pass` ; seuls les choix de consequence (CRL `uncover-*`) s'ouvrent a l'execution. Aucun champ de `G` n'est ajoute. Les cibles se choisissent a l'activation, avant l'entree en pile : `pendingChoice.targeting` ouvre chaque choix a l'activateur (`resolveChoice`), `target` (salle visee) est public sur l'entree, `picks` (cartes de la main comprises) est retire de la vue des autres sieges.
- Coup `undoBuild` (`args: [emplacement]`, sieges humains seulement, jamais l'IA) : legal tant que la salle posee CE tour par ce siege est encore face cachee et non verrouillee, donc avant son DONE (`pass`/`passBuild`) et tant qu'aucun sort ni capacite n'a ete joue depuis (par n'importe qui ; `buildRoom`, `undoBuild`, `pickBoss`, `openingDiscard` ne verrouillent pas). Effet : la carte retourne en fin de main, la salle recouverte redevient visible, `buildsThisTurn` redescend de 1. Listee dans `moves` seulement quand elle est legale (`Match._undo_build_moves`).
- Filtrage (`ViewFilter.gd`) : mains adverses, pioches (rooms/spells/heroes/epics/items), salles face cachee adverses, options des choix d'autrui
  deviennent `{"hidden": true}` (tailles conservees) ; `bossPicks` vide hors phase boss ; files internes et crochets de test retires ;
  minibosses face caches reduits a `{faceDown, hidden}` (sur la salle visible ou sur le dos d'une salle face cachee) ; journal : le moteur ecrit les lignes privees
  `{t, pub, owners}` (Match._log), le client ne recoit que du texte (`t` pour les proprietaires, `pub` pour les autres, 60 dernieres lignes) ;
  cles de joueur en liste blanche aussi (`PLAYER_PUBLIC_KEYS`). Toute cle de G inconnue est retiree (liste blanche).

## Nettoyage des salles

- Siege fantome : en salle d'attente (`open`), un siege humain NON hote dont la connexion est absente depuis plus de `--seat-grace` (30 s) est libere comme par un `leave` (le `lobby` est rediffuse ; l'ancien jeton devient `bad_token`). Un rechargement de page qui reprend (`resume`) avant la fin du delai garde son siege. L'hote n'est jamais libere par ce mecanisme : son absence ne ferme pas une salle privee (il peut partager le code dans une autre appli). Dans une salle PUBLIQUE, si l'hote reste absent plus longtemps que `--seat-grace`, le role d'hote (`start`, `setTitle`) passe au premier humain connecte (`lobby.host` change) ; l'ancien hote qui revient (`resume`) reste invite ; seule la salle publique est fermee, voir ci-dessous.
- Salle publique `open` sans aucun humain connecte depuis `--public-idle` (120 s) : fermee (`closed` aux sieges connectes, retiree de la liste). Les salles privees gardent la regle `--ttl`.
- Joueur absent en partie : un humain (hors `left`) dont la liaison est coupee depuis plus de `--abandon-grace` (120 s) est declare parti, tant qu'un autre humain est connecte, exactement comme apres un `leave` (l'IA garde le siege, `seats[i].left`, le jeton est mort, les autres recoivent « X has left the game. » ou la fin de partie par abandon). Avant ce delai, ou si plus aucun humain n'est connecte (joueur seul face aux IA, panne commune : la salle garde alors son `--ttl`), `resume` rend le siege (jusque-la, a l'echeance du delai de tour l'IA joue la decision expiree). Equivalent du retrait du joueur par Photon (OnlineFlowManager.OnPlayerLeaveGame), avec un delai de reprise que l'APK n'avait pas.
- Plafond de salles par source : NON implemente. Le serveur Godot ne voit que l'adresse de nginx (`get_connected_host()` = nginx ; les en-tetes du handshake, dont `X-Forwarded-For`, ne sont pas exposes cote serveur : `get_handshake_headers()` est vide). Une connexion ne cree qu'une salle a la fois ; l'abus (200 salles creees en se reconnectant) est borne par nginx (`limit_req` : 5 ouvertures/s par IP, rafale de 20), `--max-rooms` et le nettoyage ci-dessus.

## Limites de transport

- Trame texte : 16 Kio au plus (`MAX_PACKET_BYTES`) ; au-dela la connexion est fermee en 1009 "message trop gros" et la trame n'est pas traitee. Une trame qui depasse le tampon d'entree (`inbound_buffer_size` = 64 Kio) est coupee par Godot lui-meme (1009 cote serveur, le client voit la liaison tomber). Trames binaires ignorees.
- Debit : plus de 60 messages par seconde sur une connexion => fermeture 1008. Silence de 120 s => fermeture 1001.
- Connexions : 512 au plus sur le serveur (`max_conns`) ; au-dela la liaison est refusee des l'acceptation TCP (testee dans `online_test.gd`, `_scenario_conn_cap`). Pas de plafond PAR IP cote serveur (il ne voit que l'adresse de nginx) : voir la section nginx, dont les limites (429) sont verifiees en texte par ce meme test, faute de nginx dans la suite Godot.

## nginx (deploy/nginx.conf)

- `Origin` : `/ws` repond 403 si l'en-tete `Origin` est present et different de `http(s)://<Host de la page>` (liste blanche extensible dans le `map`). Sans `Origin` (curl, CI) : accepte. Acces local `http://localhost:8090` : accepte.
- Par IP (CF-Connecting-IP quand la connexion vient d'une adresse privee, sinon l'adresse TCP) : `/ws` 5 ouvertures/s (rafale 20) et 20 liaisons ouvertes ; site statique 30 requetes/s (rafale 100) ; depassement => 429.
